# Cycle Planner

一个本地优先的计划网页工具，用来记录任意周期内的焦点、早中晚安排和周期复盘；想法与计划按独立截止日期全局收纳，不绑定当前周期。也支持用「宏观版」管理 15-180 天的阶段规划。

## 使用

直接用浏览器打开 `index.html`，或在目录里启动静态服务：

```powershell
python -m http.server 4173 --bind 127.0.0.1
```

然后访问 `http://127.0.0.1:4173/`。

## 数据存储

默认数据保存在浏览器 `localStorage` 中。页面右侧的「GitHub 同步」面板支持把 JSON 数据同步到私有仓库：

- 默认 owner：`qiutao20`
- 默认 repository：`private_data`
- 默认 branch：`main`
- 默认 path：`weekly-planner-data.json`

需要在浏览器里填入一个拥有目标仓库 Contents read/write 权限的 GitHub token。配置会保存在当前浏览器中；计划数据仍然存放在 `private_data` 仓库，不会进入这个工具仓库。

同步逻辑参考 `qiutao20/revise_tool`：本地优先保存，手动拉取/推送，支持自动拉取和修改后防抖自动推送，并用 GitHub Contents API 的 `sha` 检查降低误覆盖风险。


## 自动同步状态

页面顶部显示同步状态。冲突、权限或网络异常会持续显示提示，可进入同步设置处理。网络和服务器临时故障会按 6–60 秒间隔重试；恢复联网、回到页面或每隔 3 分钟也会检查自动同步。同步期间的编辑会保留为待推送修改并排队上传。支持三方合并：以上次同步成功的数据为基准，自动合并不同格子、不同字段的修改。计划、想法、笔记按 ID 合并；同一字段的不同修改及删除与修改冲突需要逐项选择本地、远端或手动编辑。首次没有基准且两端不同，须确认以哪份数据为起点。基准与待处理冲突按远端目标保存在浏览器本地，刷新后可继续处理。处理期间改变的冲突内容会要求重新确认。上传遇到 SHA 冲突会重新读取远端再尝试合并。


合并逻辑与同步流程的回归验证：`node sync-merge.test.js`。测试使用模拟数据与模拟请求，不访问私有仓库。
